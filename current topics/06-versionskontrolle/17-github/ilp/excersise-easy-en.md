# Easy ILP: GitHub and Remote Repositories

## Goal

You will connect a local Git repository with GitHub.

At the end, you will have:

- a GitHub repository
- a remote connection
- tested push and pull
- a small synchronization log

## What You Need

- Git
- GitHub account
- local repository
- terminal

## Basic Tasks

### Task 1: Create a Repository on GitHub

1. Log in to GitHub.
2. Create a new repository.
3. Give it a clear name.
4. Make it public only if allowed.
5. Copy the remote URL.

**Done when:** The repository exists on GitHub.

### Task 2: Connect the Remote

1. Open your local repository in the terminal.
2. Add the GitHub URL as remote.
3. Check the remote connection.
4. Write the remote URL in your notes.

**Done when:** Local repository and GitHub are connected.

### Task 3: Push

1. Check with `git status`.
2. Make sure your changes are committed.
3. Send your commits to GitHub with `git push`.
4. Open GitHub in the browser.
5. Check if the files are visible there.

**Done when:** Your files are on GitHub.

### Task 4: Synchronize a Change

1. Change a small file on GitHub or locally.
2. Save the change.
3. Synchronize with `pull` or `push`.
4. Check the state in both places.
5. Write what happened.

**Done when:** Local and remote have the same state.

### Task 5: Write a Log

1. Create a file `sync-log.md`.
2. Write the commands you used.
3. Write what worked well.
4. Write where you had problems.

**Done when:** Your GitHub workflow is documented.

## Extra Tasks

### Extra 1: Improve README

1. Open `README.md`.
2. Add title, short description, and usage.
3. Commit and push the change.

**Done when:** Your README is easier to understand.

### Extra 2: Test Remote Change

1. Change a file directly on GitHub.
2. Get the change locally with `git pull`.
3. Check the file locally.

**Done when:** You tested pull in practice.

- What does remote mean?
- When do you use push?
- When do you use pull?
